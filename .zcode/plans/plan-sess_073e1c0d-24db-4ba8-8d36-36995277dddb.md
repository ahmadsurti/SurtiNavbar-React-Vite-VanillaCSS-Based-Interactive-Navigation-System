## Goal
Refactor the hardcoded Navbar into a prop-driven component, then build a demo-only settings panel that lets devs tweak it live and copy the config.

## Files Changed

### 1. Refactor `src/components/Navbar.jsx`
Add props with defaults matching current behavior:

```js
{
  links: [{ label, href, onClick? }],
  logo: { img, text, showText },
  cta: {
    signin:  { label, href, show },
    primary: { label, href, show }
  },
  scrollBehavior: 'pill-on-scroll' | 'always-pill' | 'static',
  glass: 'subtle' | 'strong' | 'solid',
  borderRadius: 'pill' | 'rounded' | 'sharp',
  linkHover: 'underline-grow' | 'color-only' | 'bg-pill'
}
```

Key change: links with an `onClick` field call `e.preventDefault()` + that handler instead of navigating. This is generic and useful beyond the playground.

### 2. Update `src/components/Navbar.css`
Add variant classes via data attributes on `#site-header`:
- `data-scroll="pill-on-scroll"` (default), `data-scroll="always-pill"`, `data-scroll="static"`
- `data-glass="subtle"`, `data-glass="strong"` (default), `data-glass="solid"`
- `data-radius="pill"` (default 9999px), `data-radius="rounded"` (1rem), `data-radius="sharp"` (0)
- `data-hover="underline-grow"` (default ::after animation), `data-hover="color-only"` (no ::after), `data-hover="bg-pill"` (bg on hover)

Current `.scrolled` styles become the base for `always-pill` and `pill-on-scroll` scrolled state. `static` never gets pill styles.

### 3. New file: `src/components/NavbarPlayground.jsx`
Demo-only component that:
- Manages all config state (initialized to current Navbar defaults)
- Renders `<Navbar {...config} />` with an appended "Settings" link whose `onClick` toggles the panel
- Renders the settings dropdown panel (fixed, right-aligned below navbar)
- Panel sections:
  - **Links** — list of {label, href} inputs + add/remove + up/down reorder buttons
  - **Logo** — img URL, text, showText toggle
  - **CTAs** — signin and primary: label, href, show toggle each
  - **Style** — segmented-button groups for scrollBehavior, glass, borderRadius, linkHover (3 options each)
  - **Copy Config** — generates a config object + usage snippet, copies to clipboard with a checkmark confirmation. Uses JetBrains Mono for the code block.
- Panel animation: scale(0.97) → scale(1) + opacity, glass-morphism matching the navbar aesthetic
- Uses lucide-react icons throughout (Plus, Trash2, Copy, Check, ChevronUp, ChevronDown, X, etc.)

### 4. New file: `src/components/NavbarPlayground.css`
Styles for the settings panel only. Dark glass panel, segmented controls, input fields, code output area.

### 5. Update `src/App.jsx`
Replace `<Navbar />` with `<NavbarPlayground />`. The rest of the page stays untouched.

## Copy Output Format
The copy button produces:
```js
const navbarConfig = {
  links: [...],
  logo: {...},
  cta: {...},
  scrollBehavior: '...',
  glass: '...',
  borderRadius: '...',
  linkHover: '...'
};

// Usage:
// <Navbar {...navbarConfig} />
```

## What's NOT built
- No color/font pickers (navbar consumes CSS vars, users theme via their own tokens)
- No localStorage persistence
- No mega-menu/dropdown config
- No animation speed controls
- The settings panel never ships in the Navbar component itself
